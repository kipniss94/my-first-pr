# Передача работы новой сессии (DocuView / SaasProject_v2)

Этот файл — всё, что нужно новой сессии Claude, чтобы продолжить с того же
места. Сессия должна работать **локально на ПК пользователя (Windows)**.

## 1. Задача пользователя

- SaaS-просмотрщик CAD/PDF/Office в браузере (DocuView).
- Главное: **открывать модели SOLIDWORKS в браузере в 3D без какого-либо CAD
  на ПК** — детали `.SLDPRT` (сделано: все), затем сборки `.SLDASM` (сделано:
  расстановка деталей по месту, см. §4).
- Программа лежит в `C:\User\SaaS\SaasProject_v2\` (клон репозитория, ветка
  `main`), запуск одним кликом: **`C:\User\SaaS\SaasProject_v2\Start-DocuView.bat`**.
- Модели пользователя: `C:\User\3D\SW\` (647 деталей, 110 сборок) и
  `C:\User\SaaS\Исходно\` (~2690 деталей, ~500 сборок).
- Пользователь пишет по-русски, отвечать по-русски, коротко и по делу.

## 2. Окружение на ПК (установлено в прошлой сессии)

- Git for Windows (`C:\Program Files\Git\cmd`), Node.js 24 LTS — через winget.
- Python на ПК нет (только заглушка магазина) — скрипты писать на Node.
- В оболочке агента `GCM_INTERACTIVE=never`; для входа в GitHub при `git`
  временно ставить `GCM_INTERACTIVE=always`, `GIT_TERMINAL_PROMPT=1`.
- Пользователь иногда запускает DocuView «от администратора» — такой процесс
  агент остановить не может (Access denied); попросить нажать **S** в окне.
- Для проверок, не мешая запущенному DocuView: API на другом порту
  (`API_PORT=4100 DATA_DIR=<scratch> node apps/api/dist/index.js`), веб —
  отдельная сборка `NEXT_DIST_DIR=.next-check API_INTERNAL_URL=http://127.0.0.1:4100
  next build` и `next start -p 3100`. Проверка:
  `node scripts/verify-models.mjs <папка> --assemblies --api http://127.0.0.1:4100`.
  Сборка в `.next-check` переписывает `apps/web/next-env.d.ts` и
  `apps/web/tsconfig.json` — после неё вернуть их (`git checkout -- …`).

## 3. Детали `.SLDPRT` — как устроено и что проверено

Порядок в `apps/api/src/processing/processors/cad-proprietary.ts`:
1. **Готовая сетка SolidWorks** (`Contents/DisplayLists`, `sldprt/display-list.ts`).
2. Если её нет — **точная геометрия Parasolid, триангулированная у нас**
   (`sldprt/xt-reader.ts` + `sldprt/brep-mesh.ts`).
3. Если в файле ни одного тела — «пустая деталь» (`meta.emptyModel`).

Контейнеры: современный ZIP без сигнатур (`container.ts`, имена записей — UTF-8
с перестановкой полубайтов) и старый OLE (`cfb.ts`; `documentEntries()` в
`sldprt/assembly.ts` отдаёт записи любого из двух). Сжатые записи —
GUID `231dd571…` + блоки `[u32 размер][u32 сжатый][zlib]` подряд, блоков может
быть несколько (раньше читался только первый → модели > 1 МБ обрезались).

**Parasolid XT (бинарный), выведено по файлам пользователя:**
- `"PS" <int n><заголовок> <int n><ключ схемы> <short число типов> <int user fields=0>`,
  затем узлы: `<short тип>` [при первом появлении типа: `0xff` = как в базовой
  схеме, иначе `<byte число полей>` + правки `C`/`D`/`I`/`A` до `Z`; для
  совсем нового типа — имя, описание, поля, байт-флаг] [`<int длина>` для
  типов с переменным хвостом] `<индекс>` поля. Конец — узел типа 1.
- Указатель/индекс: short, хранится на 1 больше (1 = нет); > 32767 — два
  short: `(второй << 15) | (первый & 0x7fff)`. Числа big-endian.
- В описании поля число элементов: 1 = скаляр, 2 = переменный хвост, n+1 = массив из n.
- Базовые раскладки (схема 13006) — таблица `BASE_SCHEMA` в `xt-reader.ts`,
  проверена на всех 1392 потоках корпуса (partition, ghost, LocalBodies).
- Топология: `FIN.vertex` — вершина в **конце** полуребра; направление ребра =
  направление кривой × `sense` кривой; наружная нормаль = нормаль поверхности
  × `sense` поверхности × `sense` грани; грань слева от своих контуров.
- `TRIMMED_CURVE` идёт от `parm_1` к `parm_2` (бывает по убыванию).
- `INTERSECTION`: CHART — лишь опорные точки (иногда 3 на всю кривую); точки
  между ними досчитываются проекцией на обе поверхности (`onBoth`).
- `SPUN_SURF`: рабочий участок профиля `start_param…end_param`, `start`/`end` — полюса на оси.

**Триангуляция B-rep** (`brep-mesh.ts`): каждое ребро дискретизируется один
раз (сетка без щелей), контуры переводятся в (u,v) поверхности с развёрткой
периода; полосы режутся швом «вершина к вершине», шапки замыкаются через
полюс; earcut + флипы Делоне + дробление по отклонению от поверхности.
Поверхности: плоскость, цилиндр, конус, сфера, тор, NURBS, выдавливание,
вращение, offset. Грань, которую не удалось разложить, рисуется плоско (или
пропускается, если её контур наматывается на ось несколько раз — резьба).

**Проверки (без CAD):**
- 8 эталонных деталей: объём из B-rep совпадает с SolidWorks в пределах 0,13%
  (кубы и лист — точно), сетки замкнуты и ориентированы.
- Сравнение с сеткой SolidWorks на 618 деталях: ~475 в пределах 1%, у ~80
  сетка в файле от другого состояния модели (другое число граней); остальное
  разобрано и исправлено (конус, тор, кривые пересечения).
- `C:\User\3D\SW`: 646 из 646 непустых деталей в 3D (28 — из точной геометрии,
  1 пустая «Деталь8»). `Исходно`: все детали в 3D (≈2440 по сетке SolidWorks,
  ≈240 из точной геометрии, 1 пустая).
- `npm test` — 62/62, typecheck чистый.

## 4. Сборки `.SLDASM`

- Дерево — `swXmlContents/COMPINSTANCETREE` (XML; в старых файлах `…__ZLB`,
  та же обёртка кодека). `swFile` — файлы, `swModel` — файл+конфигурация,
  `swReference` — экземпляры с `swTransform` (16 чисел: строки = образы осей
  X, Y, Z, затем сдвиг в метрах = порядок `Matrix4.fromArray` three.js).
  Положение детали = произведение матриц по пути. Верхнее дерево содержит
  всю иерархию — файлы подсборок не нужны. Разбор — `sldprt/assembly.ts`.
- Виртуальные компоненты: `VirtualComp/<имя до ^>` внутри документа
  родителя, вложенно. Их геометрия строится сразу и «запекается» в NMG сборки.
- Собственная `DisplayLists` сборки — кэш тел в их собственных координатах,
  **не** сборка: не рисовать как модель.
- API (`processAssembly` в `cad-proprietary.ts`) отдаёт `native.json` с
  `placements` (деталь, конфигурация, путь, матрица в мм) и `geometry3d`;
  список нужных файлов — уникальные внешние детали.
- Веб: `placeModels` (`lib/cad/loaders.ts`) ставит копии деталей по матрицам
  (общая геометрия, свой материал), дерево по путям экземпляров;
  `NativeCadViewer` — перетаскивание папки / кнопка выбора папки, отправляются
  только нужные файлы; исправлено: готовые компоненты после перезагрузки и
  потеря результатов при массовой загрузке (`lib/assembly.ts`).
- Проверено: BT100.00.00.000 (503 экземпляра, 75 файлов) — все 344 экземпляра
  с найденными файлами на местах, совпадает с превью; PB-600 (все 22 детали
  виртуальные) открывается без файлов.

## 5. Ограничения, которые нужно соблюдать

- **Никакого CAD** (SOLIDWORKS не использовать).
- **Не обходить защиту Windows**: без `-ExecutionPolicy Bypass`, без скриптов
  PowerShell в пользовательском сценарии, без тихих установок.
- `.bat` — только ASCII; русский текст выводит Node.
- Модели пользователя в git не коммитить (`samples/` в .gitignore; для тестов
  класть туда эталоны из корня репозитория).
- Коммиты: осмысленные сообщения; пушить в `SaasProject_1` main.

## 6. Что дальше (по приоритету)

1. Конфигурации: деталь в сборке может использоваться в другой конфигурации
   (крепёж Toolbox) — брать `Config-N-Partition` нужной конфигурации и строить
   из B-rep, когда готовая сетка сохранена для другой.
2. Крепёж SolidWorks Toolbox: файлов обычно нет в папке проекта — искать в
   `…\SOLIDWORKS Data\browser\…` на ПК или показывать габаритом из дерева.
3. Оставшиеся единичные грани (резьба по спирали, вырожденные рёбра), см.
   `stats.reasons` в логе API.
4. Цвет деталей (appearance из SolidWorks) вместо серого.
