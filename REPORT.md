# Отчёт по этапу 1 — DocuView

SaaS-сервис быстрого просмотра CAD, PDF и Office документов.
Приложение собирается, запускается и проверено на реальных файлах.

---

## 1. Что реализовано

### Загрузка и конвейер обработки

- Drag & drop и выбор файла, прогресс загрузки (реальный, через XHR), отмена.
- Стадии показываются пользователю: **Uploading → Detecting → Processing →
  Preparing geometry → Loading viewer → Ready**.
- Определение формата **по содержимому файла**, а не по расширению: magic-bytes,
  разбор ZIP/OLE-контейнеров, эвристики для текстовых форматов.
- Определение версии: `AP214`/`AP242`/`AP203` для STEP, `AC1032 → AutoCAD 2018+`
  для DXF/DWG, `PDF 1.7`, `FBX 7.4`, `Office 97-2003`.
- При расхождении расширения и содержимого файл открывается по содержимому,
  а пользователю показывается предупреждение.
- Очередь заданий с ограничением параллелизма; обработка идёт в **пуле отдельных
  процессов** — падение парсера не роняет API, лимит памяти на задание.
- Автоудаление файлов по истечении срока хранения + ручное удаление из вьюера.

### CAD-вьюер

- Навигация: вращение, панорамирование, zoom, **Fit**, **Reset**.
- Стандартные виды: Front, Back, Left, Right, Top, Bottom, Isometric
  (плюс горячие клавиши 1–7).
- Режимы отображения: Shaded, Shaded + Edges, Wireframe; регулировка
  прозрачности; сетка; снимок экрана в PNG.
- **Дерево сборки**: компоненты STEP-сборок и именованные группы OBJ;
  раскрытие, выбор, скрытие/показ, изоляция (в т.ч. двойным кликом).
- **Выбор кликом** с подсветкой; для STEP/IGES подсвечивается конкретная
  **B-Rep грань**, а не вся деталь.
- **Свойства объекта**: имя, тип, габариты X/Y/Z, min/max, объём, площадь
  поверхности, число треугольников/вершин, число B-Rep граней, цвет.
  Недоступные параметры показываются как `N/A`, объём для незамкнутой сетки
  помечается знаком `≈`.
- **Инструменты анализа**:
  - расстояние между двумя точками с привязкой к вершинам (+ ΔX/ΔY/ΔZ);
  - длина ребра модели (соседние коллинеарные сегменты объединяются, поэтому
    ребро 100 мм измеряется как 100 мм, а не как один треугольник);
  - угол по трём точкам с отрисовкой дуги;
  - габаритный ящик для всей модели или для выбранной детали.
- **Сечения**: включение/выключение, выбор оси X/Y/Z, плавное перемещение
  плоскости, разворот направления, отображение и штриховка среза.

### PDF-вьюер

Страницы с непрерывной прокруткой и ленивым рендерингом, панель миниатюр,
zoom (fit width / fit page / шаги), переход к странице, **полнотекстовый поиск**
с подсветкой и счётчиком совпадений, печать, скачивание, полноэкранный режим,
текстовый слой (текст можно выделять).

### Office-вьюеры

- **Word** — HTML с сохранением заголовков, списков, таблиц и изображений;
  регулировка ширины колонки и размера шрифта; переключение на **точную
  постраничную вёрстку** (генерируется по требованию).
- **Excel** — виртуализированная сетка (в DOM только видимые ячейки), все листы,
  объединённые ячейки, числовые форматы, базовые стили, закреплённые заголовки.
- **PowerPoint** — рендеринг слайдов через LibreOffice + панель слайдов
  с заголовками и заметками докладчика, прочитанными прямо из OOXML.
- CSV/TSV и обычный текст.
- Изображения (PNG, JPEG, GIF, WebP, BMP, SVG).

### Сайт и подготовка к монетизации

- Главная с CTA и зоной загрузки, посадочные страницы `/cad-viewer`,
  `/pdf-viewer`, `/office-viewer`, а также `/about`, `/privacy`, `/terms`.
- SEO: title/description, Open Graph, Twitter card, JSON-LD (WebApplication и
  FAQPage), `robots.txt`, `sitemap.xml`, семантическая вёрстка, favicon.
- Компонент `AdSlot` с зарезервированными размерами (top / sidebar / in-content
  / footer). **По умолчанию выключен** — сеть не подключена, скрипты не грузятся.
  Реклама вынесена так, что не может перекрыть 3D-вид: правая колонка появляется
  только на очень широких экранах.
- Guest mode без регистрации; архитектура готова к добавлению аккаунтов.

## 2. Архитектура

```
packages/shared    Реестр форматов и контракты API ↔ вьюер.
                   Единственный источник правды о поддержке форматов.

apps/api           Express: приём файла, валидация, очередь заданий,
                   хранилище, сборщик просроченных файлов, REST API.
  processing/      Слой обработки. Запускается в пуле дочерних процессов.

apps/web           Next.js: посадочные страницы (SSR, для поиска) и вьюеры
                   (клиентские, вынесены в отдельные чанки).
```

**Ключевое решение — пул тёплых процессов обработки.** Сначала на каждое задание
запускался отдельный процесс: это давало изоляцию, но добавляло ~2 секунды на
старт интерпретатора и WebAssembly к *каждому* CAD-файлу. Пул сохраняет
изоляцию (падение или перерасход памяти убивают один воркер, а не API; воркер
перезапускается после 25 заданий и по простою), но убирает холодный старт из
критического пути: **STEP-файл стал открываться за 161 мс вместо 3236 мс.**

**Нормализованная геометрия (NMG).** Результат OpenCascade сохраняется как
JSON-манифест + один бинарный буфер с типизированными массивами. Браузер
отдаёт буферы в WebGL без пофакторного разбора JSON, а дерево сборки и
структура B-Rep граней сохраняются. Этот формат — точка развязки: движок CAD
можно заменить, не трогая вьюер.

**Реестр форматов** читают и загрузчик, и роутер API, и таблицы на сайте.
Поэтому интерфейс физически не может обещать формат, который конвейер не умеет.

## 3. Использованные библиотеки

| Библиотека | Зачем |
| --- | --- |
| `occt-import-js` (OpenCascade, WASM) | Чтение STEP/IGES/BREP: тесселяция B-Rep, дерево сборки, грани |
| `three` | Рендеринг 3D, загрузчики STL/OBJ/PLY/glTF/3MF/FBX/COLLADA, OrbitControls, CSS2D-подписи |
| `dxf-parser` | Разбор DXF (рисование — собственный Canvas-рендерер) |
| `pdfjs-dist` | Рендеринг PDF, текстовый слой, извлечение текста для поиска |
| `mammoth` | DOCX → семантический HTML |
| `exceljs` | Чтение XLSX: значения, стили, объединения, форматы чисел |
| `fast-xml-parser` + `adm-zip` | Разбор OOXML презентаций (структура, заметки, запасной рендерер) |
| LibreOffice (внешний процесс) | DOC/XLS/PPT/ODF, слайды PPTX, точная постраничная вёрстка |
| `express`, `multer`, `helmet`, `express-rate-limit`, `cors` | HTTP-слой и базовая защита |
| `pino` | Логи (вся техническая информация остаётся здесь) |
| `next`, `react`, `tailwindcss` | Frontend |
| `@playwright/test` | Браузерные тесты |

**Почему так, а не иначе.** OpenCascade — единственный открытый ядровый
движок, который читает STEP/IGES по-настоящему; собственное ядро не писалось
(п. 19 ТЗ). Мешевые форматы разбираются в браузере: у three.js уже есть
корректные загрузчики, и это убирает лишний круг обращения к серверу.
LibreOffice выбран для Office вместо чисто-JS решений, потому что вёрстка
презентаций — это и есть смысл формата, и ни одна JS-библиотека её не
воспроизводит.

## 4. Что реально поддерживается

Проверено загрузкой настоящих файлов через реальный API (16/16 проверок).

| Формат | Статус | Комментарий |
| --- | --- | --- |
| STEP (.step/.stp) | **Full** | Проверено: AP214, дерево сборки, B-Rep грани, объём, сечения |
| STL (бинарный и ASCII) | **Full** | Проверено обоими вариантами |
| OBJ | **Full** | Группы становятся узлами дерева; внешние .mtl не подгружаются |
| DXF | **Partial** | Проверено: LINE, LWPOLYLINE, CIRCLE, ARC, TEXT, слои. 3D-тела в DXF не рисуются |
| PDF | **Full** | Проверено: рендер, навигация, поиск, zoom, печать |
| DOCX | **Full** | Проверено: заголовки, списки, таблицы, изображения |
| XLSX | **Full** | Проверено: 2 листа, формулы (значения), формат `#,##0.00`, объединения |
| PPTX | **Full** | Проверено: 3 слайда через LibreOffice + структура и заметки |
| CSV / TXT | **Full** | Проверено |
| IGES | **Partial** | Код общий со STEP (тот же движок), **но на реальном IGES-файле не тестировался** |
| BREP | **Partial** | То же: код есть, файла для проверки не было |
| glTF / GLB | **Partial** | Загрузчик подключён, на файле не тестировался |
| 3MF, PLY, FBX, COLLADA | **Partial** | Загрузчики подключены, на файлах не тестировались |
| DOC, XLS, PPT, ODT, ODS, ODP, RTF | **Conversion** | Путь через LibreOffice реализован и работает (проверен на DOCX→PDF), но на самих legacy-файлах не тестировался |
| DWG | **Conversion** | Требуется внешний конвертер; **в этой среде его нет, путь не проверялся**. Без него пользователь получает понятное сообщение |
| SolidWorks, Inventor, CATIA, Parasolid, JT, IFC, Revit | **Planned** | Определяются по имени, не рендерятся. Показывается сообщение с советом экспортировать в STEP |
| PNG, JPEG, GIF, WebP, BMP, SVG | **Full** | Простой просмотр |

Я намеренно не ставил «Full» там, где формат не открывался живьём.

## 5. Что пока не реализовано

- **DWG** — нужен внешний конвертер (ODA File Converter или LibreDWG).
  Точка подключения есть (`DWG_CONVERTER_CMD`), но здесь она не проверена.
- **Проприетарные CAD-форматы** (SLDPRT, IPT, CATPart, X_T, JT) — не рендерятся.
- **IFC/BIM** — распознаётся, не рендерится (планировалось на этап 2).
- **Диаграммы и сводные таблицы Excel** не рисуются; показываются ячейки.
- **Формулы не пересчитываются** — отображается последнее сохранённое значение.
- **Заполнение PDF-форм и проверка подписей** не реализованы; OCR нет.
- **Сложная вёрстка Word** (текстовые блоки, колонки, колонтитулы) упрощается в
  структурном виде — для этого есть режим точной вёрстки.
- Кривые рёбра в измерении длины: измеряется прямой отрезок между концами.
- **Прогрессивное превью** до окончания обработки не сделано — вместо него
  честные именованные стадии.

## 6. Тестирование

### Как получены тестовые файлы

Все фикстуры генерируются локально (`npm run fixtures`), сторонних файлов в
репозитории нет. Для этого написан `scripts/step-builder.mjs` — минимальный
генератор STEP AP214 (плоские B-Rep тела), включая **настоящую структуру сборки**
с `NEXT_ASSEMBLY_USAGE_OCCURRENCE`, — иначе имена компонентов не доходят до
вьюера, и проверить дерево сборки было бы нечем.

Использованные файлы: `cube.step`, `hollow-block.step` (сквозное отверстие —
для проверки сечения полой геометрии), `bracket-assembly.step` (сборка из двух
именованных деталей), `broken.step`, `stepped-block.stl`, `cube-ascii.stl`,
`two-part.obj`, `plate.dxf`, `report.pdf`, `inspection-report.docx`,
`bill-of-materials.xlsx`, `pipeline-overview.pptx`, `measurements.csv`,
`notes.txt`, `not-a-model.stl` (текст под видом STL), `garbage.bin`.

### Результаты

| Проверка | Результат |
| --- | --- |
| Юнит-тесты API (`npm test`) | **14 / 14** — определение формата, безопасность путей, санитайзинг HTML, очередь, автоудаление |
| Прогон всех фикстур через реальный API | **16 / 16** |
| Браузерные тесты, Chromium (desktop) | **38 / 38** |
| Браузерные тесты, мобильный профиль | **5 / 5** |
| Production-сборка | Успешно, без ошибок типов |

Браузерные проверки закрывают чек-лист из п. 27 ТЗ: главная без ошибок в
консоли, drag & drop (реальный `drop` с файлом), file picker, STL и STEP,
вращение/zoom/панорамирование/fit, все семь стандартных видов, режимы
отображения, выбор объекта, измерение расстояния, плоскость сечения,
дерево и изоляция компонентов, DXF со слоями, битый файл, PDF (страницы,
навигация, поиск, zoom), DOCX, XLSX, PPTX, удаление файла и восстановление
документа после перезагрузки страницы.

### Производительность (эта машина, 4 ядра)

| Файл | Время до готовности |
| --- | --- |
| STEP (куб, сборка) | ~161 мс |
| STL, OBJ, DXF, PDF | ~160 мс |
| DOCX, XLSX, CSV | ~160 мс |
| PPTX (LibreOffice, прогретый) | ~2.1 с |
| PPTX (первая конвертация после старта ОС) | ~13.6 с — LibreOffice строит кэш шрифтов |

Первая загрузка главной страницы: 114 кБ JS. three.js и PDF.js в этот объём
**не входят** — они загружаются только когда открывается соответствующий файл.

### Браузеры

- **Chromium** — протестирован полностью (WebGL через SwiftShader).
- **Мобильный профиль (Pixel 7)** — протестирован.
- **Firefox** — **проверить не удалось**: в этой среде нет бинарника Firefox,
  а CDN Playwright заблокирован. Конфигурация для Firefox в проекте есть
  (`npm run test:e2e` запустит его там, где браузер установлен).
- **Safari / WebKit** — по той же причине не проверялся.

Скрытых допущений о Chrome в коде нет: используются стандартные API
(WebGL 2, ResizeObserver, IntersectionObserver, Fullscreen), но честно говоря —
пока это проверено только в Chromium.

## 7. Найденные проблемы и их статус

Всё найденное в ходе тестирования исправлено; ниже — что именно.

| Проблема | Статус |
| --- | --- |
| LibreOffice в системе стоял без пакетов writer/calc/impress — любая конвертация падала с «source file could not be loaded» | **Исправлено**: пакеты установлены; приложение теперь проверяет наличие фильтров при старте и предупреждает |
| Холодный старт процесса обработки добавлял ~2 с к каждому CAD-файлу | **Исправлено**: пул тёплых воркеров, 3236 мс → 161 мс |
| Куб обрезался при вписывании в кадр: радиус считался по стороне, а не по диагонали габаритного ящика | **Исправлено** |
| Штриховка сечения не отображалась: координата в шейдере умножалась на масштаб, хотя уже была в мировых единицах — полосы становились меньше пикселя | **Исправлено** |
| Меню видов не открывалось: `overflow-x-auto` на нижней панели обрезал всплывающий блок | **Исправлено**: меню позиционируется относительно окна |
| После перезагрузки страницы вьюер зависал на «Opening…» — в URL оставался мёртвый идентификатор сессии | **Исправлено**: при отсутствии сессии происходит восстановление по `job`, `s=` из URL убирается |
| Дерево модели показывало только узлы; отдельные детали внутри узла не отображались | **Исправлено** |
| Счётчик FPS показывал «3 fps» в покое (рендер по требованию) и выглядел как тормоза | **Исправлено**: счётчик скрывается, когда сцена не перерисовывается |
| В дереве вместо имени файла показывалось название формата | **Исправлено** |
| Импорт любого процессора подтягивал `runner.ts`, который слушает stdin — тесты зависали | **Исправлено**: контракт вынесен в отдельный модуль |
| PDF: панель миниатюр была скрыта по умолчанию | **Исправлено**: открыта по умолчанию |
| 404 на favicon | **Исправлено** |

Остаётся известным (не дефект, а ограничение): имена компонентов в дереве
берутся из структуры STEP-сборки. Если в файле несколько тел лежат в одном
представлении без структуры сборки, OpenCascade отдаёт их как «Solid 1»,
«Solid 2» — имён там просто нет.

## 8. Как запустить

```bash
npm install
npm run fixtures     # необязательно: создаёт тестовые файлы в ./fixtures
npm run dev
```

Открыть <http://localhost:3000>. Поднимаются оба сервиса: API на порту 4000,
веб на 3000.

Через Docker (LibreOffice уже внутри образа):

```bash
docker compose up --build
```

---

## 9. Как остановить

`Ctrl + C` в терминале с `npm run dev` останавливает оба сервиса.

```bash
docker compose down        # остановить
docker compose down -v     # остановить и удалить сохранённые документы
```

---

## 10. Production-сборка

```bash
npm install
npm run build
NODE_ENV=production npm start
```

Перед портом 3000 поставить обратный прокси и терминировать TLS на нём.

## 11. Что нужно установить

| Компонент | Версия | Для чего |
| --- | --- | --- |
| Node.js | 20.11+ (рекомендуется 22) | всё приложение |
| npm | 10+ | всё приложение |
| LibreOffice | 7.x+, **обязательно с пакетами writer, calc, impress** | DOC, XLS, PPT, ODF, слайды PPTX, точная вёрстка |
| Конвертер DWG | ODA File Converter или LibreDWG | только для DWG |

```bash
sudo apt install libreoffice-writer libreoffice-calc libreoffice-impress
```

Отдельно ставить CAD-ядро **не нужно**: OpenCascade поставляется как
WebAssembly-модуль в составе npm-зависимостей.

Без LibreOffice приложение работает: DOCX, XLSX, PDF и все CAD-форматы
открываются; PPTX рендерится упрощённым встроенным рендерером; legacy Office
форматы сообщают, что конвертер отсутствует.
